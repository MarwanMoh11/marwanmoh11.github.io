TELOS II — Senior Thesis

Team of 7 · lead

FastAPI · Python · React · LLM evaluation

Measuring LLM sycophancy: can a recommendation adapt to evidence while resisting conversational pressure? The architecture's answer is that the model renders but never decides — action authority sits in a versioned, SHA-256-pinned YAML policy behind an independent decision guard, and the renderer gets a deep copy so it cannot mutate the decision.

Evaluation protocol is predeclared: 288 outputs per model per domain, with parse failures counted rather than silently discarded and a runtime fallback treated as a delivered outcome, not an exclusion. The README states plainly what it is not.

Station 04 — Instrument 02

The same throw, the same seed, a different score

A real bug from CARRY. settled() is not monotone — a knocked pin can roll, go quiet, then hit something else. The shot end was polled once per rendered frame, so a 120 Hz phone stopped inside quiet windows a 30 Hz laptop stepped straight over, and read the rack at a different simulation step.

The fix, and the honest footnote. Latch the shot end inside Alley.step() on the simulation clock, and give Alley.run() ownership of step batching — the render rate stops being an input to the score. Both divergent throws are kept verbatim as regression tests. Station 05 — Instrument 03

Why ordering hurts

GeoFighters negotiates one channel per peer pair, id 0, ordered:false, maxRetransmits:0. At 30 Hz only the newest snapshot matters, so a lost packet should cost you one frame — not stall every frame behind it. Drag the loss up and watch the reliable lane stutter.

What stays on the reliable path. Not everything wants this trade. Low-rate traffic that must arrive exactly once — shoot events, chest opens, revives, game-over — deliberately stays on the socket.io relay. And when ICE fails, which it does on roughly 10–15% of networks without TURN, the channel simply never opens and that one peer keeps using the relay. The design degrades per-peer, not per-session.
